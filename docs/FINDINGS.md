# 实际运行发现与处理

以下来自实际 Trace、原生观察或部署检查。代码回归证明修复满足相应契约，真实逐局结果见 [验证记录](VERIFICATION.md)；两者不能互相替代。

| 问题 | 实际影响 | 当前处理与边界 |
| --- | --- | --- |
| 目标和资源互相阻塞 | 经济角色额外消费共享资源，生产目标长期得不到推进；模型解释也可能与动作不一致 | 提供当前阶段、角色目标与实际缺口，展示机械可用工具、真实队列和拒绝回执；共享预算顺序按轮次轮换。阶段由框架定义，不能称为模型自主分解任务 |
| 已完成角色仍持续消费 | 角色完成分工后继续请求模型，可能另造建筑、重复侦察或发明新目标 | v3 协调器将该角色置为等待，记录 `coordination.role_wait`，请求数为 0；新阶段目标出现后再激活。等待不伪造成模型回复，也不代选游戏动作 |
| 等待可能漏掉必要供给 | 生产还需人口时，经济角色若无当前目标会提前等待；供给达标后还可能因战损下降 | 备战末阶段显式要求人口上限至少 30，`maintain=true` 按实时缺口唤醒经济；历史达标时间仍锁存，其他目标不因损失而一律重做 |
| 采气命令可能过量分配 | 重复转移矿工会削弱采矿；一次指令接受不能证明工人已经到达或采到气 | 原生执行器依据实际 assigned/ideal harvesters 与本批预订限制气矿容量；容量未知时不猜。回执保留请求和接受分配，后续实际采集另看观察 |
| 侦察单位身份不连续 | 重复默认侦察可能抽走新的矿工；建造也曾选中远处侦察 SCV | 默认复用跟踪的合法侦察单位，显式单位选择仍校验资格；建造优先近处合格工人，不抢移动或施工中的工人。单位到达仍由后续观察确认 |
| 原生矿物 snapshot 被漏掉 | 仅筛 `mineral_contents>0` 会丢掉储量未报告的中立矿物，扩张候选只剩开局一簇 | 按原生矿物类型与位置识别 snapshot；未报告储量不当作枯竭，可见且明确为 0 才排除。位置已知不等于 Agent 实地侦察发现 |
| 零请求角色污染总 token | 首两局长程中，未调用角色的空用量账本使原始全局总量变为 null | 统计器将零请求用量计为已知 0；发生请求但用量缺失仍保持 null。历史原值保留，网页仅在角色调用次数与总数对齐、相应用量完整时标注账本汇总，不重写证据 |
| 历史输入增长与服务错误 | 初版完整历史模型局出现超时和服务错误 | 已使用有界历史摘要、角色输入投影及有限纠正。硬件、模型和上下文曾一起改变，不报告单项加速比例 |
| 消息可能传播未证实进展 | 角色广播的“完成”不一定出现在游戏观察中 | 保留消息、真实动作、回执和观察，支持通信开关对照；消息不能作为任务验收证据，也不能从单局判断通信收益 |
| 跨阶段历史保留过期目标 | 首次扩张后胜利模型局在扩张完成后，输入仍含“第二基地未完成”等旧历史和团队消息；生产可用却未请求造兵 | v4 在阶段切换时归档旧阶段输入，保留原始 Trace，传入交接事实及持续职责；真实效果另按新局记录，不预先声称获胜 |
| 字符预算不等于 token 窗口 | 长局经济输入实际超过 8,192-token 服务窗口，导致请求被拒绝 | 预防性减少历史字符预算；仅对结构化上下文超限裁剪旧历史并在原次数与总超时内重试。缺失用量仍未知，不更改原失败局 |
| 模拟传输掩盖部署依赖 | TestClient WebSocket 通过，但早期实际服务缺少 WebSocket 实现 | 已补运行依赖并检查真实 TCP/WebSocket；仍需区分 Mock、浏览器与原生游戏验证 |
| 指令初始接受后仍可能失败 | 旧建造记录反复出现 CouldntReachTarget，初始 ACK 容易被误当成完成 | 建造前结合原生放置、工人能力和路径查询；后续原生错误按单位、能力和命令身份关联，另记执行失败或部分失败。无法唯一关联的错误保留为未关联，不强行归因；路径预检不是最终建造保证 |
| 只保留可用工具会丢失依赖知识 | full_match 中无补给站，兵营不可用，模型说建兵营却选工程站 | 保留完整团队工具知识、前置条件和负责角色，另列当前可用许可和原生阻塞信息。不能因动态 schema 合法就认定策略正确；真实修复效果看后续对局 |
| 继续执行与停止命令混淆 | 已在攻击的 Marine 被模型用 hold 停下，同时理由仍写继续攻击 | 明确空动作保留现有订单，hold 下达 HOLD POSITION 并取消行进命令；用当前订单和部队实际分散距离作事实摘要。合法 attack 仍不被策略规则拦截 |
| 有限工具集与想象中的科技树不一致 | 模型采集 3,100 气体，却缺少仅需矿物的陆战队和工人 | 明确当前 gas 消费仅为武器 1 级研究，未提供其他兵种或更高等级工具；说明是领域知识，不由框架自动调整采矿或代选经济动作 |
| 输出空间被 8K 输入占满 | 部分返回以 length 结束，JSON 被截断；追加纠错反而增加输入 | 同一模型服务显式改为每槽 16K 并核对实际容量；保存安全逐次诊断，确认触及已知容量时仅有限移除旧历史。配置窗口与自动探测严格区分 |
| 当前 JSON 超限导致零请求 | 16K 局仍有 6 次战术输入超过自己的 24K 字符保护 | 上限保持不变，超限时有限去重、去战术角色外明细、裁剪带标记的己方样本；保留任务、当前敌目标、失败与侦察位置订单。原始 Trace 完整保留，不称字符界为 token 保证 |
| 既有工作被误当成未付款的新请求 | 模型称已开工兵营仍缺原建造价，或称采更多气能加速既有研究，影响产兵 | 用正向生命周期说明和简短示例区分新请求成本、已观察施工/队列及就绪空闲；研究进度不自动占用另一座兵营，施工能否推进仍看工人和订单 |
| 当前目标被历史坐标覆盖 | 可见补给站 `(38,134)` 满血，模型却攻击旧坐标并称它已受损 | 明列有界当前敌目标及真实血量，说明 attack-move 目的地与出生点先验的区别；全军血量统计与少数重伤样本分开。坐标示例使用不同数值，不自动替模型选目标或下达攻击 |

当前 v3 基础任务已有三个固定种子通过，扩张供给和升级备战各有一个真实模型样本通过。它们证明这些配置下能执行任务，不能外推为普遍稳定、长程成功率或完整对局胜利。历史未完成、错误和原生战败记录保留。

后续重点是固定版本、模型、地图和预算，分别比较通信与执行指导，并检查长程作战失败。阶段提示、角色等待、工具修复等是多项累计变更，现有前后结果不能归因于其中某一项；模型等待期间整个游戏暂停，也不能据此宣称实时对抗能力。系统不会在模型失败时静默切换为脚本或沙盒。
