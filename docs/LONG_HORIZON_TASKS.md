# 长程任务与评测工作表

目的：让同一套真实 SC2 环境承担多阶段任务，检验模型与工作流能否持续推进、协调资源并依据反馈纠错。当前仍是一个人族玩家中的三个功能角色，对抗内置电脑。

任务阶段和角色职责由实验定义提供，系统显示真实目标缺口；这属于**有阶段指导的任务执行**，不应宣称模型已经自主完成开放式任务分解。不会用规则策略在模型失败时接管。

## 任务

| 任务 | 需要连续完成什么 | 主要检查什么 | 建议游戏预算 |
| --- | --- | --- | --- |
| 扩张与资源供给 `expansion_logistics` | 建立开局产能 → 观察中已知远离开局的资源位置、达到 24 工人并建成第二基地 → 两座精炼厂及累计采集 200 气体 | 资源信息可用性、持续供给、先决条件、跨阶段恢复角色 | 900 秒 / 至多 180 轮，每轮 224 loops |
| 升级步兵备战 `army_readiness` | 建立开局产能 → 两座兵营、工程站及累计 100 气体 → 完成步兵武器 1，升级后同时观察到 12 名 Marine，并维持足够人口容量 | 经济与生产协调、等待研究完成、队列和实际部队区分 | 1,200 秒 / 至多 240 轮，每轮 224 loops |
| 扩张后赢下对局 `expansion_and_victory` | 建立开局产能 → 已知扩张资源位置、24 工人与两个独立基地 → 引擎实际报告 Victory | 长期资源、扩张与作战衔接、失败恢复和最终胜负 | 2,400 秒 / 至多 360 轮，每轮 224 loops |

以上是实验配置建议，**不是已经取得的任务成绩，也不是最低运行时长**。提前达标即可结束；轮数和游戏时间任意一个预算先到均结束。不同步进量下，轮数与游戏时间的关系不同。

三个长程任务推荐完整对战地图 `AbyssalReefLE`，其资源条件与机械动作链已有原生脚本验证。Qwen3-8B 已各一次通过前两项任务；第三项完整对局样本战败。具体成绩和配置见验证记录。基础及旧任务保留推荐 `Simple64`。使用其他地图时需先验证真实资源位置、扩张命令和建成结果，地图名、seed、版本和资源条件必须随结果保存。

## 判定依据

- 工人、建筑与兵种取真实引擎观察；生产队列、指令接受或模型声称完成都不算完成。
- 第二基地要求真实完成且位置与另一基地相距至少 12；已知资源位置要求引擎报告的资源簇距开局位置超过 16。位置来自中立单位 snapshot，开局可能已知；位置已知不等于 Agent 实地侦察发现，也不能单独作为侦察协作有效的证据。
- 累计采气使用原生 `score.collected_vespene`，升级使用真实完成升级列表。字段缺失记未知，不补零或猜成功。
- Marine 的 12 人目标只在武器 1 已完成后计数，避免“先有过 12 人、全死后再升级”也通过。
- 一般目标达标后保留首次达标记录；显式 `maintain=true` 的人口供给还会按当前状态重新激活责任角色。
- 原生 Defeat 始终是失败；预算耗尽是未完成。达到多个阶段不等于赢下整局。

## 主要指标

| 层面 | 记录 | 怎么解读 |
| --- | --- | --- |
| 最终效果 | success / failure / incomplete / error / stopped，各自样本数 | 所有启动尝试都保留，不只统计成功局 |
| 长程推进 | 完成阶段数 / 总阶段数，里程碑数 / 总数，各阶段首次达标游戏时间 | 有进展但没完成不算任务成功；不同任务的进度率不直接混排 |
| 时间效率 | 成功局完成游戏时间、现实时间；有效角色响应与整轮决策各自 p50/p95 | 预算结束的局不填“完成耗时”；模型等待时游戏世界暂停 |
| 调用成本 | 实际请求次数、输入/输出 token，未知用量保持 null | 协调器等待不计为模型调用，不伪造模型回复 |
| 动作质量 | 接受 / 拒绝 / 提议数、拒绝比例及原因分布 | 接受不等于有效或任务完成；空动作也可能是正确等待 |
| 原生游戏结果 | Victory / Defeat / Tie，原生采集、花费、战损等可用统计 | 与专项任务结果分开保留 |
| 协作与框架效果 | 同模型通信开/关、执行指导开/关的同配置重复对照 | 需要多个固定种子及重复局，单局不能推导稳定收益 |

建议先固定 `Qwen3-8B`、地图和预算跑通，再比较模型或框架。每次改动保留源码指纹、任务版本、配置与原始记录，不能把新旧不同条件的结果称为严格单项加速实验。

## 当前调试顺序

1. 用基础建造侦察任务检查实际动作与角色生命周期，保留成功和失败局。
2. 用显式脚本基线验证扩张、采气、升级和地图条件，成绩明确标为脚本。
3. 使用真实 Qwen3 依次尝试长程任务，记录停在哪个阶段以及具体回执。
4. 条件固定后做多个样本对照，报告成功数、失败类型和成本，不预填成功率指标。

实际成绩以 [验证记录](VERIFICATION.md) 为准；运行命令及完整统计口径见 [EXPERIMENTS](EXPERIMENTS.md)。
